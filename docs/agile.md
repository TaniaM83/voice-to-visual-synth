# Agile y metodologías de desarrollo

1. ¿Qué es Agile?
    Agile es un enfoque de desarrollo de software iterativo basado en la flexibilidad, la colaboración y la entrega continua de valor. Promueve ciclos cortos de trabajo, Los métodos ágiles, que a menudo se denominan marcos, son enfoques completos de las fases del ciclo de vida de DevOps: planificación, desarrollo, entrega y operaciones, suelen tener una duracion de una a cuatro semanas, exige adaptaciones frecuentes y una comunicación constante entre el equipo.

    # Objetivo de Agile en el desarrollo de software
        El objetivo principal de Agile es producir software útil de manera rápida y eficaz. Busca reducir riesgos, mejorar la calidad y permitir que los equipos respondan con agilidad a las necesidades reales.

2. ¿Qué es Scrum?
    Scrum es un marco de trabajo que implementa los principios de Agile, estructura el proceso de desarrollo en ciclos cortos llamados sprints. Cada sprint es un periodo estable de trabajo en el que el equipo planifica, desarrolla, prueba y entrega una versión funcional del producto.

    # Conceptos principales de Scrum
        - Roles:
            - Product Owner: representa al cliente o negocio y define las prioridades del producto.
            - Scrum Master: facilita el proceso, elimina impedimentos y se asegura de que el equipo siga las prácticas de Scrum.
            - Equipo de desarrollo: grupo multifuncional responsable de construir y entregar el producto.
        - Sprints: periodos de tiempo fijos (generalmente 1 a 4 semanas) en los que se completa un conjunto definido de tareas.
        - Backlog:
            - Product Backlog: lista priorizada de todas las funcionalidades, mejoras y tareas necesarias para el producto.
            - Sprint Backlog: selección de elementos del Product Backlog que el equipo se compromete a completar durante un sprint.
        - Reviews: reuniones al final de cada sprint donde el equipo muestra lo entregado y obtiene retroalimentación del Product Owner y otros interesados.

3. ¿Qué es Kanban?
    Kanban es un método visual para gestionar tareas que se centra en el flujo de trabajo. Utiliza tarjetas y columnas para mostrar el estado de cada actividad, lo que ayuda al equipo a ver qué se está haciendo, qué sigue y cuáles son los cuellos de botella.

    # Cómo se usa Kanban para organizar tareas
        - Se crea un tablero con columnas que representan etapas del proceso, como "Por hacer", "En progreso" y "Hecho".
        - Cada tarea se representa con una tarjeta que se mueve de una columna a otra conforme avanza.
        - Se establecen límites de trabajo en curso (WIP limits) para evitar que el equipo tenga demasiadas tareas al mismo tiempo.
        - El equipo revisa el tablero continuamente para detectar bloqueos, equilibrar la carga y mejorar el flujo.

## Diferencias entre Scrum y Kanban
- Estructura: Scrum trabaja con ciclos temporales fijos (sprints), mientras que Kanban es continuo y no requiere sprints.
- Roles: Scrum define roles específicos (Product Owner, Scrum Master, equipo de desarrollo); Kanban no impone roles formales.
- Planificación: Scrum planifica el trabajo dentro de cada sprint; Kanban permite una planificación más fluida y flexible.
- Medición: Scrum usa métricas como velocidad de sprint; Kanban se enfoca en el tiempo de ciclo y el flujo de tareas.
- Cambio: en Scrum no se suelen incorporar cambios durante el sprint; en Kanban los cambios pueden introducirse al flujo continuo.

## Situaciones para usar cada metodología
- Scrum es útil cuando el proyecto se puede organizar en entregas periódicas y se requiere claridad en roles y responsabilidades. Funciona bien con equipos que necesitan planificación estructurada y revisiones frecuentes.
- Kanban es apropiado cuando el trabajo llega de forma continua o cuando se busca mejorar el flujo de tareas sin imponer ciclos fijos. Es ideal para equipos de mantenimiento, soporte o proyectos con prioridades cambiantes constantes.

## Conclusión
Agile es una filosofía que busca entregar valor de forma continua y adaptarse al cambio. Scrum y Kanban son dos formas distintas de aplicar Agile: Scrum aporta estructura con sprints y roles definidos, mientras que Kanban aporta transparencia y flexibilidad en el flujo de trabajo. Cada metodología se elige según la naturaleza del proyecto y el estilo del equipo.
